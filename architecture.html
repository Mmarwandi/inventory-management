Component Pattern

All views use Vue 3 Composition API with reactive state in refs, derived data in computed properties, and async data loading with try-catch error handling. Filter state is managed through shared composables for consistency across views.

Key Patterns

Reactivity Pattern

Raw data stored in refs (allOrders, inventoryItems), derived data in computed properties. Changes to filters trigger new API calls, updating refs, which automatically cascade to computed properties and re-render the UI.

Filter Application

Frontend passes filter values as query parameters → Backend applies filters sequentially → Returns filtered subset → Frontend stores in refs → Computed properties derive display values → Vue renders reactive UI.

Data Validation

Pydantic models validate all API responses. If JSON data structure changes, corresponding Pydantic models must be updated. All dates use ISO 8601 format, and enums enforce valid status values.

Development Notes

• No Database: All data is loaded into memory at server startup. Changes don't persist across restarts.

• CORS Enabled: Backend allows all origins for development. Production deployments should restrict this.

• Auto-reload: Vite provides hot module replacement for frontend. Backend restarts manually.

• API Documentation: FastAPI generates interactive docs at http://localhost:8001/docs

• Revenue Goals: System tracks against $800K/month target, $9.6M annual goal.
